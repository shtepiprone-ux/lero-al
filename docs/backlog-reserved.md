| **759** | reserved — **no sprint yet**, filed 2026-08-18 by the Sprint 60 reviews | **A detector for the unlayered-Mantine cascade trap.** `@mantine/core/styles.css` ships with no `@layer` wrapper; Tailwind utilities live in `@layer utilities`; unlayered always wins regardless of specificity or source order. So **any Tailwind class on a Mantine component that competes with a declaration that component's own root class sets has never rendered** — and a migration that "faithfully preserves" it into a working prop or CSS Module *introduces* a change. This shipped twice in one sprint and both times only review caught it: **752** (`justify-start`/`text-left` on `Button`, whose root is `display:inline-block` with `text-align:center` — the prop replacement moved labels 16.1px) and **756** (`leading-snug` on `Text`, whose root sets `line-height: var(--text-lh, …)` — moving it into `.cardTitle` cut every listing-card title from 20.02px to 19.25px). A repo-wide scan found **109** Tailwind classNames sitting on Mantine components, mostly in admin surfaces; `rounded-xl h-10 text-xs` on a `Button` and `text-xs px-1.5` on a `Badge` were measured completely inert. The detector: for each Tailwind class on a Mantine component, resolve the property it sets, read the component's own compiled CSS in `node_modules/@mantine/core/styles/<Component>.css`, and flag the pair when Mantine sets the same property. **This is also a live answer to Sprint 55's standing exit criterion** ("name the detector that would have caught these, or record in writing why none is worth building") — owner decides whether it lands there or in its own sprint. Task **757**'s AC9 makes the manual version mandatory for `AuthSheet`; this number is the automated version. |
