# Opus task-design parent workflow

This parent is the task-design checklist. It routes to short phase files; it is not permission to skip them or to
read the entire rules repository by default.

## Non-negotiable visual rule, loaded first

A kickoff never authorizes a consumer/Story hardcode. It must name the inspected canonical component/Story and the
semantic token path. If the token or pattern does not exist, scope its creation in the shared registry and direct
Story before consumer integration. For every changed element type, require a built-Storybook census proving one
semantic meaning has one look across existing Stories, or record the dated owner decision that distinguishes contexts.
For visible scope, select the semantic compact profile, registry-allowed Mantine mechanism, and canonical Mantine
owner in `shared/mobile-adaptation-contract.md` before any token or component decision. Mantine owns responsive
mechanics; the contract adds only semantic order/content treatment/proof. Existing Stories are proof targets, not
design authorities. A missing family/profile/mechanism/owner is `BLOCKED — MOBILE PATTERN EXTENSION REQUIRED` until
Opus extends the registry before publication; Sonnet never fills that gap. `shared/enforcement-model.md` is
mandatory: a rule-only receipt is not enough when the repository
gate fails or a newly enrolled component lacks its component → token-owner → Story contract.

## Ordered checklist

| When | Read and complete | Publication blocker |
|---|---|---|
| Before task/source/diff | `.claude/rules/create/01-preflight.md` + `shared/claim-evidence-contract.md` | unsupported facts, missing source-backed mobile pattern, missing reference research, reserved/sprint conflict, or missing UI census |
| While writing kickoff | `.claude/rules/create/02-kickoff-contract.md` | missing claim ledger/citations, multiple routes, local visual values, no direct Story/token owner, or incomplete AC/QA contract |
| Before handoff | `.claude/rules/create/03-publication.md` | `check:kickoff-evidence` failure, stale/contradictory kickoff, incomplete rule evidence, failed backlog gate, or unreconciled paths |

The first substantive response begins with the exact receipt in `create/01-preflight.md`. Read only the task-specific
bundle chosen via `docs/rule-index.md`, plus the phase files above. Detailed historical/policy definitions remain in
the cited documentation.

## Role boundary

Create/revise task and required state artifacts; do not implement product code or approve an implementation. A
published task gives fresh Sonnet one saved executable route, not a chat-only or dual-path handoff.
