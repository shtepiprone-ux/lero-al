# Checklist U — visible UI (design D8, implementation I5, review V5, V9)

Only for a task that changes what a user sees. Under checklist A: the smallest change, and what `main` shows stays.
The `shared/` file a line names holds its detail.

| # | Check | Done when |
|---|---|---|
| U1 | **Reuse first** (`shared/canonical-component-reuse.md`): search `src/design-system/mantine/` and the Stories by purpose; REUSE, else EXTEND the owner and its Story, else CREATE the smallest shared Mantine component with its Story | the kickoff names the owner and its Story; no duplicate component |
| U2 | **Legacy leaves** (owner, 2026-11-19): a file the Fix changes loses its `@/components/ui/*` imports, Tailwind classes and legacy admin wrapper, keeping every control, option, validation, position, colour and label of `main` (example: a `type="number"` field becomes `NumberInput`, which keeps the step arrows) | the migrated component is enrolled in `scripts/mantine-migration-scope.json` with no baseline entry |
| U3 | **No local visual value** (`shared/ui-token-contract.md`): no `style`, `styles`, `className`, colour, size, radius, spacing or shadow literal in a consumer or Story; a missing token is added at the theme first | the diff has none |
| U4 | **One meaning, one look**: the same element in every Story and component that renders it uses the same tokens, compared from code | the kickoff or review lists the compared Stories with `path:line` |
| U5 | **Mobile below 640 px** (`shared/mobile-adaptation-contract.md`): the kickoff's "## Mobile adaptation record" names the pattern, the Mantine mechanism and owner; no required text is clipped (`lineClamp`, ellipsis, `nowrap`) | the record is complete; the code matches it |
| U6 | **Stories** (`shared/storybook-proof.md`): under `Mantine/Primitives/*` or `Patterns/Mantine/*`, one page per component; data and documented props only; `StoryPageGutter`; no fixed width or viewport pin; every production state, also of each changed child; interactive as in production; consistent fixtures | each changed Story checked from its code |
| U7 | **Product details** (`docs/rules/golden/`): a table has checkboxes first, content, edit then delete last, bulk delete and a confirm (GR-8); a person's name wraps (GR-3i); blocks keep their container's spacing token (GR-3h); text buttons in a popup stack (GR-3e); headings below 640 px are at most 20 px (GR-3c) | each applicable line answered |
| U8 | **Overlays**: a Story that opens one has its rows in `scripts/rendered-interaction-states.json` (`shared/rendered-state-census.md`) | rows present |
| U9 | **Rendered proof** is the CI Storybook jobs on GitHub and the owner's own check of the Stories; no model builds Storybook, runs a census, probe or screenshot set | — |
| U10 | **External references** (`shared/reference-research.md`) only for a decision no canonical component covers | the pages used are named with their URLs |
| U11 | **States of a new screen or component** (from the "UI States and Edge Cases" skill of the Product Designers pack): default, loading, empty, error, partial, success, disabled, no permission, offline; plus the longest real content, the longest of the four locales, 320 px, a slow or failed request | the kickoff marks each state "built" or "not needed: <reason>"; a list has an empty state, a load has loading and error |
| U12 | **Accessibility from the code** (from the "Accessibility Review" skill, WCAG 2.2): text and control colours come from theme tokens whose contrast is known (1.4.3, 1.4.11); meaning is never colour alone (1.4.1); every control has a visible label (3.3.2); an error names the field and what to do (3.3.1); focus stays visible and unhidden (2.4.7, 2.4.11) | each applicable line answered from the code; screen-reader and real-device behaviour is the owner's check, never claimed |
