# Checklist V — Opus reviews a task (skill `review-task`)

Every item, in this order, under checklist A. The review judges the diff against its kickoff; it is not a new design.

| # | Step | Done when |
|---|---|---|
| V1 | `node scripts/quality/owasp.mjs sync`, `check`; `node scripts/quality/check-ruleset.mjs`; `gh run list --branch main --limit 3` | all exit 0; the state of `main` CI is named |
| V2 | **Scope first:** `git diff --stat <commit the revision started from>` against the kickoff's Scope | a file outside the Scope, or a hunk the Cause does not need, is a finding whose fix is to revert it |
| V3 | **The report is a supplier assertion:** rerun each claim (the Route's tests, the failing-first runs, the deliberate breaks); when any `.ts` or `.tsx` file changed, `npm run typecheck` once; when any code file changed (`.ts .tsx .mts .cts .js .jsx .mjs .cjs`), `npx eslint --no-warn-ignored --max-warnings 0 <every changed and new code file of the diff>` once, the pre-commit hook's command (owner, 2026-11-25); and every test that imports a changed module, found by import in the whole tree (`grep -rlE "<module path>|<exported name>" src --include=*.test.ts --include=*.test.tsx`), never by folder, not only the Route's | a claim that does not reproduce is a finding; a type error is a finding; an ESLint error or warning is a finding |
| V4 | Read every changed file once, tests included; a generated file through the tool that checks it | a change that does not remove the "## Cause" is a finding |
| V5 | Approved behaviour: each changed surface against `git show main:<path>` and its `main` Story | a change of what `main` does without an owner decision is a finding (A2) |
| V5a | **Rendered comparison of every changed visible element** (owner, 2026-11-23): (1) Pages: on the app dev server (`http://localhost:3000`, the owner's session in the owner's Chrome through the browser extension), open every page that renders an element the diff changes, including the other pages of a changed shared component; (2) Stories: on the Storybook dev server (A5), every changed Story and every Story of a changed component, in every state it renders, at 320, 640, 1024 and 1440px. Read each element's computed style: height, radius, border colour and width, padding, font size and weight, text colour, shadow, and the focus, error and disabled states. Compare it with its canonical primitive Story, with the same element type elsewhere on the page or in the other Stories, and with `main` (`git show main:<path>` and production). An interactive change (a control, a hover or focus state) is also checked in Firefox, from the owner's look when no Firefox is reachable. A page that needs database objects not yet applied is `BLOCKED: <the missing object>`, never skipped | the review lists each page and Story with each element's measured values and its comparison; any difference without a dated owner decision is a finding; no verdict before this step |
| V6 | Exemptions: every added or removed allowlist, baseline, registry row, `skip`, `eslint-disable` in the diff | each is proven with a planted bad case through the same checker, or is a finding |
| V7 | Secure code review: `.claude/rules/secure-code-review.md` §2 (the six steps) and §3 (every category); data or roles: `db-catalog-audit.mjs`; uploads: `node --env-file=.env.local scripts/quality/cloudinary-config.mjs` | every category of §3 answered: "touched" with `path:line`, or "not touched" with the fact (`git diff --name-only` shows no file of it) |
| V8 | Each acceptance criterion: run its test, undo the product change once, run again, restore | the test fails without the change |
| V9 | Stories for the owner: list each changed Story and the states it renders, with the measurements of V5a (2) | the owner checks the Stories by hand last; the reviewer's own Storybook measurement (V5a) comes first and is never replaced by this list |
| V10 | `node scripts/quality/owasp.mjs review <kickoff> --base main`; write `docs/security/owasp/reviews/Task_<n>.json` | every listed sheet is `met`, `finding` or `not applicable` with its reason |
| V11 | Findings: only defects of this diff against the kickoff, A2 or OWASP. No new requirement, redesign or "nice to have"; a new idea is one line proposing a numbered task. Each finding's revision item says exactly what to change | every finding cites `path:line` and the rule it breaks |
| V12 | Write `docs/reviews/Task_<n>_Review_<k>.md` (`secure-code-review.md` §4, §5), link it in "## Review"; `node scripts/quality/check-files.mjs <kickoff> <review file>` | exit 0 |
| V13 | Verdict: `APPROVED`, `APPROVED WITH NOTES` or `NEEDS REVISION`. `NEEDS REVISION`: the same response first hands the owner the commands for a local commit of the reviewed tree (checklist H1-H3, no push; Opus's uncommitted documentation and rules may stay out of it, I1), then ends with the prompt for the executor's session (owner, 2026-11-23, translated: "If the status of the task is Needs Revision, you must always give the prompt for the executor at once"): `/execute-task`, the kickoff path, the commit the revision starts from, the Revision block and its items, the review file, the tests to write and run, and what the report must contain; the next review's V2 diffs against that commit | every note is fixed now or is a numbered task; a `NEEDS REVISION` response carries the commit commands and the executor's prompt, which names the base commit |
| V14 | After the owner's push: `gh pr checks <n>` | every check concluded; a red job is opened with `gh run view <id> --log-failed` and fixed in the same pull request |
