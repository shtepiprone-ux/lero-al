## Summary

Implements the Mantine `Switch` primitive per the new §6h state matrix (extracted from `src/components/ui/switch.tsx`).
All §6e/§6f/§6g lessons baked in up-front. Key Switch-specific findings from source analysis (Switch.mjs + InlineInput.mjs):

1. **`data-error` on the TRACK** (`Switch.mjs ~L153 mod:{error,...}`) — different from Checkbox/Radio where it's on the input.
2. **Adjacent-sibling combinator** for focus/unchecked rules: `input.mantine-Switch-input` precedes `.mantine-Switch-track` in DOM, so `input:focus-visible + .mantine-Switch-track` works.
3. **No Part 2 disabled reset**: the input has `opacity:0` for visual hiding (not `0.6` for disabled), so resetting it to 1 would un-hide the hidden a11y input. Root `:has(:disabled)` opacity 0.5 is the sole mechanism.
4. **Unchecked track color**: `var(--color-input)` = neutral-300 (#DEDEDE) from the source `bg-input` token. §6d documents "gray-200" but the actual `--input` CSS variable is neutral-300 (#DEDEDE, between gray-2/#e4e7ec and gray-3/#d0d5dd). Mantine's own default is gray-3. Using the exact design-system token; owner to verify in DevTools.
5. **Error inset box-shadow**: the Mantine Switch track has no base border (unlike source switch.tsx which has `border border-transparent`). Used `inset 0 0 0 1px` box-shadow to simulate a border without layout shift.

## Key design decisions

**DOM structure (confirmed from Switch.mjs + InlineInput.mjs):**
```
.mantine-Switch-root (Box — InlineInput root)
  .mantine-Switch-body (label element, bodyElement="label")
    input.mantine-Switch-input (type=checkbox, role=switch; opacity:0, pos:absolute — visually hidden)
    .mantine-Switch-track (span, aria-hidden; carries [data-error] via mod:{error,...})
      .mantine-Switch-thumb (span)
      .mantine-Switch-trackLabel (span)
    .mantine-Switch-labelWrapper ([data-disabled?])
      .mantine-Switch-label (span; [data-disabled?])
      .mantine-Switch-error (Input.Error)
```

**Resting unchecked specificity:**
- `.mantine-Switch-input:not(:checked) + .mantine-Switch-track` = (0,3,0)
- Beats Mantine's base `background-color: var(--switch-bg)` at (0,1,0) ✓
- `:not(:checked)` prevents overriding the checked brand fill ✓

**Error specificity:**
- `.mantine-Switch-track[data-error]` = (0,2,0) — box-shadow only, no `background-color` conflict with resting rule ✓
- `.mantine-Switch-root[data-checked] .mantine-Switch-track[data-error]` = (0,4,0) — beats error rule for checked+error ✓

**Size decision (density correction):** `size='sm'` (20px track) kept per density-correction note (§6 header, Task 492). Source-of-truth is 18.4px × 32px — closest match is `sm` in height; `xs` matches width (32px). Owner to verify in DevTools.

## Critical difference from Checkbox/Radio disabled pattern

| Component | Mantine input opacity | Part 2 reset? |
|-----------|----------------------|---------------|
| Checkbox | 0 (visual hiding) | Not applicable — reset is for opacity:0.6 disabled |
| Radio | 0 (visual hiding) | Not applicable |
| **Switch** | **0 (visual hiding — permanent, NOT disabled)** | **NO — would un-hide the hidden input** |

Checkbox/Radio Part 2 reset targets `opacity:0.6` that Mantine sets on their inputs when disabled. Switch input has `opacity:0` for visual hiding (always, not just when disabled). Resetting Switch input to `opacity:1` via `:disabled` selector would override the visual-hiding `opacity:0`, making the hidden checkbox input visible at 50% opacity over the track.
