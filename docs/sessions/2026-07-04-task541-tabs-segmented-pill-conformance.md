## Origin / context

Task 539 Scope C surfaced a STOP-AND-ASK: `tailadmin-style-reference.md` §6c + §6l both state TailAdmin's
canonical tab bar is segmented/pill, not underline — but `Tabs.stories.tsx` rendered Mantine's default underline
variant. Owner decision (2026-07-04): convert Tabs to segmented/pill so nothing differs from TailAdmin. A first
pass implemented the pill chrome, but the owner then rejected it — the horizontal swipe-on-overflow was broken:
`.mantine-Tabs-list { width: 100%; }` pinned the gray track to the ScrollArea viewport width at `<640`, so when
uk/sq/it labels overflowed at 320px the track never grew to contain all three pills and the last pill clipped past
the track edge on swipe. The kickoff's CORRECTION section specified the exact fix.

**State found at session start (uncommitted, in the working tree already):** Step 0 (removal of the stale Task 539
underline text-color block) and the segmented/pill chrome itself (`theme.ts` `Tabs` defaultProps/styles,
`input-chrome.css` `.mantine-Tabs-tab`/`[data-active]`/hover rules, `Tabs.stories.tsx` variant switch) were already
present — confirmed via `git diff` before touching anything. **This session's actual fix was the CORRECTION only:**

```css
/* before (bug) */
.mantine-Tabs-list { width: 100%; }
@media (min-width: 640px) { .mantine-Tabs-list { width: fit-content; } }

/* after (this session) */
.mantine-Tabs-list {
  width: fit-content;
  min-width: 100%; /* <640 — full-width when labels fit; grows to content on overflow */
}
@media (min-width: 640px) {
  .mantine-Tabs-list { min-width: 0; /* §6c ≥640 — content-width, NOT stretched */ }
}
```

`width:fit-content` + `min-width:100%` = `max(content, viewport)`: full-width bar when it fits (mobile gate), and
a content-width bar that scrolls whole (gray background + all pills + both rounded ends move together) when it
overflows — exactly the CORRECTION's required fix, byte-identical to the kickoff's cited CSS.
