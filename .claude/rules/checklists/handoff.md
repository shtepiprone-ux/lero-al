# Checklist H — Opus hands commands to the owner

Every item, in this order, under checklist A, before any commit, push, pull request or merge command.

| # | Step | Done when |
|---|---|---|
| H1 | Local: `git status --short --branch`, `git log --oneline main..HEAD`; for a merge or switch also `git diff --name-only <base>...<branch>`. GitHub (read-only `gh`): `gh api repos/:owner/:repo/commits/main` (the `main` SHA there), `gh pr list --state open`, `gh run list --branch main --limit 3` (a red run is opened with `gh run view <id> --log-failed`), and the branch to be pushed: `gh api "repos/:owner/:repo/branches?per_page=100"` | the state is named, local and on GitHub: local `main` against GitHub `main`, open pull requests, the cause of a red `main` run and which pull request fixes it, whether the branch name is free; the current branch first; the handoff says on which branch each commit lands and why; documentation alone (`docs/`, `tasks/`, `*.md`: an archive, a backlog row, a kickoff, a review, a rule) never gets its own pull request: it stays uncommitted and lands in the first commit of the next task branch, so CI runs once for both; a documentation-only pull request only when the owner orders it; when the work does not belong to that branch's task, the first command creates its branch from `main` (`git switch -c <branch> main`) or says why it cannot yet; an uncommitted file the merge would overwrite is committed first; no subagent is changing the tree |
| H2 | Every file of the commit (`git diff --name-only main...HEAD` plus every uncommitted file) against the documentation read in A0, kind by kind: code or configuration (anything but `docs/`, `tasks/`, `*.md`) → `quality-gates.md` §5 "OWASP task gate": its kickoff, an `APPROVED` review file and `docs/security/owasp/reviews/Task_<n>.json` are in the same pull request; code → §5 "CodeQL": no regular expression, path or shell string is built from input; `docs/backlog.md` → GR-5: no closed-state marker outside "Last Session" (`✅`, `CLOSED`, `APPROVED`, `ARCHIVED`, `FOLDED`, "archived <date>", "folded into"); a kickoff → `kickoff-template.md` and its mobile record; every file → `quality-gates.md` §1. No CI gate is run locally to do this (A5) | the handoff lists each kind of file of the commit with the documented rule and how the commit satisfies it |
| H2a | Write what the owner does first: read the diff, approve rule and sensitive-path changes, wait for checks | written before the commands |
| H3 | The commands, for a separate PowerShell 5.1 window, in the order they run, each written right the first time: before the reply is sent, every command is checked against the publication hook's rules (`~/.claude/hooks/publication-rules.mjs`, owner 2026-11-24): a push is `git push origin <branch>` (`-u` only on the first push of the branch), nothing else; a merge is `gh pr merge <n> --squash` (optionally `--delete-branch`); no push of `main`, no refspec, no force or other option; a push or `gh pr create` already done is never handed again (read `git rev-parse origin/<branch>` and `gh pr list --head <branch>` first); a bare `git push` is not written in the reply at all, not even when quoting the owner | the first line of each says what it changes (local only, GitHub, `main`, production); `git add` names every file; no attribution; a command made unnecessary later is withdrawn at once; no command of the reply is refused by the publication hook |
| H4 | SQL the owner runs: run its preflight and rollback checks read-only, with LF and with CRLF; compare `md5` | both pass; no backup question (`project-facts.md`) |
| H5 | After the push: `gh pr checks <n>` | every check concluded; a failure is fixed in the same pull request |
| H6 | Merges, one at a time: read `scripts/quality/main-ruleset.json` (the branch must be up to date with `main`); hand over one merge command, for one pull request whose `CI Required` is green; then `gh run list --branch main --limit 3` until the `main` run of that merge has concluded. Only then the next pull request: one command to bring it up to date with `main` (`gh pr update-branch <n>`), `gh pr checks <n>` until every check has concluded, then its one merge command | the handoff holds one merge command; the `main` run of each merge is named green before anything is handed over for the next pull request |
| H7 | After each merge, once its `main` run is green (`gh run list --branch main --limit 3`): archive the task (GR-5) — the kickoff to `tasks/Archive/`, its review link updated, one newest-first row in `docs/backlog-archive.md` (verdict, pull request, merge commit, `main` run), its row and number out of `docs/backlog.md`, its status in the sprint plan's Tasks table; rewrite "Last Session" (2-4 lines, the latest sessions); then read every section of `docs/backlog.md` and remove or correct each row whose task is merged, archived or has a ledger row, the fact named; `npm run check:backlog-active`; then the merged branch leaves (owner, 2026-11-24; GitHub keeps a merged branch, `delete_branch_on_merge` is `false`): read `gh pr view <n> --json state,headRefName,headRefOid` and `gh api repos/:owner/:repo/branches/<branch>` (the branch tip equals the pull request head, so nothing was added after the merge) and `gh pr list --state open --head <branch>` (none), then hand the owner its deletion: on GitHub through `https://github.com/<owner>/<repo>/branches` (the publication hook refuses a command that deletes a ref there), locally `git branch -D <branch>` (a squash merge is not an ancestor of `main`, so `-d` refuses) once the owner is on another branch, then `git fetch --prune origin` | exit 0; every row left is still to be done or decided; the changes wait uncommitted for the next task branch (H1); the merged branch is handed over for deletion with the three facts read, or kept with the fact that keeps it |
