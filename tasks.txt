- Задача 12: Задача: Реалізувати в адмін‑панелі повний функціонал керування профілем користувача для ролей Admin та Moderator за принципами marketplace‑продуктів типу OLX або RIA, де адміністратор або модератор може створювати, переглядати, редагувати та видаляти профіль користувача строго в межах цієї задачі без будь‑яких змін у сторонніх частинах продукту.
Профіль користувача обовʼязково має включати аватар у форматах JPG, PNG або WEBP з можливістю завантаження, заміни та видалення і відображенням дефолтного плейсхолдера при відсутності фото.
Також профіль має містити обовʼязкову базову інформацію у вигляді імені та прізвища, email‑адреси, яка є обовʼязковою і має бути підтверджена, а також типу користувача, який може бути admin, moderator, private person, agent або developer і визначає доступність та обовʼязковість інших полів.
Контактні дані повинні складатися з обовʼязкового основного номера телефону у міжнародному форматі та окремого поля для номера WhatsApp з можливістю використати основний номер, при цьому обидва поля мають проходити валідацію.
Для всіх типів користувачів без винятків обовʼязково має бути вказана локація у вигляді населеного пункту в Албанії (combobox), при цьому регіон визначається автоматично на основі населеного пункту і відображається лише для читання, де для admin, moderator і private person населений пункт означає місце реєстрації, а для agent і developer — місто діяльності.
Для агентів та забудовників додатково відображаються спеціальні поля, серед яких назва компанії є обовʼязковою, а посада та рік початку діяльності є необовʼязковими.
Профіль також повинен підтримувати керування статусом акаунта зі значеннями active, suspended і blocked, де при виборі blocked причина блокування є обовʼязковою.
Має бути відображена історія всіх змін у статусах профілю, а також вказана інформація з ім'ям користувача та датой і часом внесеної зміни.
Сторінка профілю завжди відкривається у режимі перегляду і переходить у режим редагування лише після явної дії користувача, має кнопки збереження та скасування, при цьому натискання Cancel завжди без виключень відкриває підтверджуюче вікно з попередженням про втрату всіх незбережених змін. Створення користувача реалізовується окремим флоу з мінімально необхідним набором полів та встановленням пароля через лист відновлення, після чого відбувається редірект у режим перегляду профілю.
Видалення користувача доступне лише адміну, завжди потребує підтвердження з відображенням імені та email і виконується як soft delete, при цьому вся реалізація має включати повну валідацію полів та не виходити за межі файлів, напряму повʼязаних із функціональністю профілю користувача.

- Задача 19: Implement full user profile management in the admin panel for Admin and Moderator roles, following marketplace best practices similar to OLX, DOM.RIA and AUTO.RIA, where an administrator or moderator can create, view, edit and delete a user profile strictly within the scope of this task and without touching unrelated parts of the project. Each user profile must include an avatar with enforced constraints of exactly square dimensions 256×256 pixels, supported formats JPG, PNG or WEBP and maximum size 2 MB, with the ability to upload, replace or remove the avatar and fall back to a default placeholder if none is provided. The profile must also contain mandatory basic information including first name and last name, an email address that is required and becomes read‑only after user creation, and a user type that can be admin, moderator, private person, agent or developer and controls which fields are shown and required. Contact information must include a required primary phone number in international format and a separate WhatsApp phone field with an option to reuse the primary phone number, with validation applied to both. Location data must always be required for every user type and consist of a city selected via autocomplete from Albanian settlement with the region automatically derived from the city and displayed as read‑only, where the city represents place of registration for admins, moderators and private users and place of activity for agents and developers. For agent and developer profiles only, additional fields must be shown including a mandatory company name, optional position and optional year when activity started. The profile must also support account status management with values active, suspended and blocked, where choosing blocked requires entering a mandatory block reason. The profile page must open in view mode by default, switch to edit mode only after explicitly clicking an edit action, and provide save and cancel actions, where pressing cancel must always show a confirmation dialog warning that all unsaved changes will be lost and allow the user either to confirm cancellation or return to editing with no exceptions. User creation must be implemented as a dedicated flow with minimal required fields, automatic password generation and password setup via reset email, after which the user is redirected to the profile view mode. Deleting a user must be restricted to admin only, require a confirmation dialog showing the user’s name and email and perform a soft delete. All validations must be handled correctly with clear error feedback, and no refactoring, UI changes or fixes outside files directly related to user profile management are allowed.
Checklist: The system must ensure that an admin can create, edit and delete user profiles while a moderator can only view and edit them and cannot delete users or change their role. The user profile must always open in a read‑only view mode and never start in edit mode. The avatar upload must reject files that are not JPG, PNG or WEBP, exceed 2 MB or are not 256×256 pixels, and replacing or removing the avatar must work correctly with a visible default placeholder when no avatar exists. First name and last name must be required fields and the email field must be immutable after the user is created. The primary phone number must be mandatory and validated as an international phone number, while the WhatsApp phone must support copying the primary phone when the corresponding option is enabled and still be validated. City selection must be mandatory for all user types, must use autocomplete, must correctly set the region automatically and must not allow manual editing of that region. Company name must be required only when the user type is agent or developer, and agent or developer specific fields must disappear immediately when the user type is changed to a different value. Changing the account status to blocked must always require entering a block reason and must prevent saving without it. Entering edit mode must require an explicit user action and saving must correctly persist all changes and return the profile to view mode. Pressing cancel must always trigger a confirmation dialog warning about lost changes and must never silently discard edits. Creating a user must enforce all required fields and result in a redirect to the profile view mode after completion. Deleting a user must be available only to admins, must show a confirmation dialog with identifying user information and must perform a soft delete. All field‑level and submission errors must be visible and understandable, and the implementation must not introduce any changes outside the user profile feature.
