(FiltersPanel/HeroSearch → Mantine, Epic MM Phase-2 composite migration). The three leaf filter

## Implementation

**`src/components/shared/FilterRangeInputs.tsx`** — two legacy `@/components/ui/input` `Input`s →
Mantine `TextInput` ×2, `className="flex-1 min-w-0"` each (preserves the even-split row inside the
parent's `flex gap-2`). `type`/`min`/`placeholder`/`value` map 1:1; `onChange={e =>
onXChange(e.currentTarget.value)}` emits the identical string. Chrome (`h-11`, `rounded-lg`, border,
focus ring, `shadow-theme-xs`) comes for free from the global `input-chrome.css`/`theme.ts` — no
custom className needed, matching §6e verbatim without inventing anything.

**`src/components/shared/FilterMultiToggle.tsx`** / **`FilterRoomsRow.tsx`** — legacy
`@/components/ui/button` `Button`s → Mantine `Button`, `variant={selected.includes(...) ? 'filled' :
'default'}` (replaces `'default'`/`'outline'`). Mantine's `theme.ts` `Button` defaults already provide
`minHeight: 2.75rem` (44px), wrapping labels (`whiteSpace: 'normal'`), `radius: 'lg'`, and the §6a
bordered `default`-variant chrome globally (Task 527/528 established this once for the whole app) —
so no custom sizing/radius/height className was added, only `justify-start text-left` on
`FilterMultiToggle` (explicitly required by the kickoff to preserve left-aligned wrapped labels,
since Mantine's Button content is center-justified by default) and `shrink-0` on `FilterRoomsRow`
(unchanged from the kickoff's literal composition spec — no forced square width added, since the
existing height token + natural content padding already produces a compact, roughly-square look for
1–2 character room labels, confirmed in the rendered evidence below).

`primaryColor: 'brand'` is already the `theme.ts` default, so `variant="filled"` resolves to the
brand `#EC5447` fill without an explicit `color` prop.
