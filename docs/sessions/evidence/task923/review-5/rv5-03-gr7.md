Primary sources, fetched live this session:

1. WCAG 2.2 Understanding SC 2.5.8 — https://www.w3.org/WAI/WCAG22/Understanding/target-size-minimum
   Literal (definition of target): "region of the display that will accept a pointer action, such as the interactive
   area of a user interface component".
   Reading: a control clipped wholly outside its frame has no region of the display, so it is not a pointer target.
   Hidden from assistive technology and out of the tab order, it is not an action for anyone. Applied in kickoff §14 R24.
   A control inside the frame, even hidden and untabbable, keeps being measured.
2. WAI-ARIA APG Carousel — https://www.w3.org/WAI/ARIA/apg/patterns/carousel/
   Literal: "screen reader experience can be confusing and disorienting if slides that are not visible on screen are
   incorrectly hidden". Unchanged since review 4. A slide that is only moved off-screen remains a defect; R24 needs
   both hidden-from-AT and out-of-tab-order, so the gallery desync (a tabbable, named slide off-screen) still fails.
3. WAI-ARIA APG Dialog (Modal) — https://www.w3.org/WAI/ARIA/apg/patterns/dialog-modal/
   Literal (Tab): "Moves focus to the next tabbable element inside the dialog." / "If focus is on the last tabbable
   element inside the dialog, moves focus to the first tabbable element inside the dialog."
   Reading: the requirement is where the focus lands. A transient `body` focus that settles inside the dialog within
   the poll window is not a landing; R26 (b) judges the settled element. A focus that settles outside still fails.
